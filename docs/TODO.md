# Bike backlog

Updated: 2026-10-04. This is the only active Bike checklist. The Rust backend
owns application behavior; the shared UI, gateway, and renderer retain their
own service responsibilities. [Product specifications](../bike-rs/docs/specs/README.md)
describe intended behavior; this file records remaining work and its evidence.

## Operating scope

Plan for about ten new activities per day. Prefer focused happy-path checks and
small fixes driven by actual use. Keep ownership, input validation, source
retention, deduplication, retries, and provider quota handling. Expand concurrency,
load tests, and failure rehearsals when an observed bug or measurement warrants it.

Use models for queries, services for workflows, and controllers for HTTP
adaptation. Preserve historical migrations and durable job compatibility.
Work one bounded ID at a time and commit its result with a conventional message.
Compilation, fixture behavior, executed SQL, native memory, and live recovery
are separate forms of evidence. A pending row stays pending until its stated
verification is recorded.
